# Timing Colour Tool

Apply hue-based colour variations to child projects in the [Timing](https://timingapp.com/) time-tracking app. Parent folder colours stay the same; every child, grandchild, and deeper project gets a distinct but related shade.

> **Runs entirely in Terminal.** No tkinter, no GUI frameworks, no third-party packages — just the Python standard library.

---

## Setup

Unzip, `cd` into the folder, and run:

```bash
chmod +x setup.sh
./setup.sh
```

This creates a Python virtual environment **in the same folder**. No packages are installed — the tool uses only the standard library. The venv just isolates things cleanly.

---

## Usage

### Interactive mode (recommended)

```bash
./timing-colours
```

Walks you through everything step by step: finds your database, lets you set variation strength, previews changes with a dry run, then applies.

### Command-line mode

```bash
# Preview changes without saving
./timing-colours ~/Library/Application\ Support/info.eurocomp.Timing2/SQLite.db --dry-run

# Apply with recommended variation
./timing-colours ~/Library/Application\ Support/info.eurocomp.Timing2/SQLite.db --variation 35

# Reproducible result using a fixed seed
./timing-colours ~/Library/Application\ Support/info.eurocomp.Timing2/SQLite.db --variation 35 --seed 42
```

### Arguments (command-line mode)

| Argument | Description |
|----------|-------------|
| `db_path` | Full path to the Timing `SQLite.db` file |
| `--dry-run` | Preview changes without saving |
| `--variation N` | Strength 0–100 (default: 15). Recommended: 25–40 |
| `--seed N` | Fixed random seed for reproducible colours |

---

## Variation Guide

| Strength | Effect |
|----------|--------|
| 10 | Very subtle — almost the same as parent |
| 20 | Gentle — noticeable but closely related |
| **35** | **Recommended** — distinct family colours |
| 50 | Strong — significant hue shift |
| 75+ | Extreme — may leave the parent's colour family |

---

## Safety

- **Quit the Timing app** before running.
- A **timestamped backup** is created automatically before any changes.
- **Dry run** mode makes zero changes to your database.
- To undo: copy the `.backup_` file back over `SQLite.db`.

---

## How It Works

Each child colour is generated by converting the parent's hex colour to HSV, applying random shifts to hue (±8% × strength) and saturation (±70% × strength) with minimal brightness change, then converting back to hex. Because each child uses its own new colour as the base for its children, the variation compounds naturally down the tree.

The script auto-detects the correct table and column names by inspecting the database schema, so it works across different versions of the Timing app.
